# Moudie NetPlay — سجل تحقق الإصدار 1.4.4

**تاريخ التحقق:** 18 أغسطس 2026
**حزمة التسليم:** `MoudieNetPlay-v1.4.4-arm64-release.apk` لنظام Android `arm64-v8a`
**معرّف التطبيق:** `com.app.moudienetplay`
**رقم البناء:** `27`

## نطاق الإصدار

يعالج هذا الإصدار سبباً جذرياً لتوقف المحاكيات داخل الغرف: كانت إشارة البدء المحفوظة في ذاكرة خدمة الوقت الفعلي قد لا تبقى متاحة عند انتقال المستخدم من واجهة الغرفة إلى المشغّل الأصلي. أصبحت الخدمة تعيد إنشاء حاجز الجلسة من الحالة النشطة المحفوظة للغرفة، ثم تسمح لمشغلي PS1 وPSP/Sega/Arcade بالتحقق من ملف اللعبة والنواة نفسها وإكمال بدء الجلسة. بقيت ملفات اللعبة وBIOS محلية تماماً على أجهزة اللاعبين.

أضيفت قائمة لعب جانبية في المشغلات الأصلية تضم **CHAT وMIC وSAVE وLOAD وEXIT**، وتُحفظ مواضع وحجوم عناصر HUD لكل نظام ولكل اتجاه شاشة. كما أصبحت شاشة Famicom قابلة للسحب والتكبير والتصغير من وضع إعداد التحكم، واكتمل توحيد لوحة الاتجاهات فيها إلى أزرار مربعة مرجعية قابلة للمعايرة بدلاً من الشكل الدائري القديم.

## نتيجة التحقق

| الدورة | نطاق التحقق | النتيجة |
|---:|---|---|
| 1 | اختبارات وحدة تطبيق Android `pnpm test` | نجح: 14 ملف اختبار ناجحاً، 30 اختباراً ناجحاً، وملفان متخطيان متوقعان. |
| 2 | فحص TypeScript `pnpm check` | نجح: لا أخطاء TypeScript. |
| 3 | فحص ESLint `pnpm lint` | نجح: لا أخطاء أو تحذيرات ESLint؛ ظهر إشعار Node عام حول نوع ملف الإعداد فقط. |
| 4 | تجميع Kotlin `:moudie-emulator:compileReleaseKotlin` | نجح بعد إضافة HUD والقائمة الجانبية ومعايرة شاشة Famicom ولوحة الاتجاهات المربعة. |
| 5 | اختبار وحدة خدمة الغرف `pnpm test -- server/netplay.test.ts` | نجح: اختبر الحضور والدردشة والإشارات ومدخلات lockstep وحاجز البدء واستعادة حاجز PS1 من غرفة نشطة. |
| 6 | اختبار إنتاجي PS1 | نجح: بدء الغرفة عبر API ثم اتصال مشغلي PS1 فقط واستعادة الحاجز ومقاعد اللاعبين. |
| 7 | اختبار إنتاجي PSP/Universal | نجح: استعادة الحاجز وإشارة bootstrap لنظام PSP؛ والمسار ذاته يستخدمه Sega وArcade. |
| 8 | اختبار إنتاجي Famicom | نجح: جاهزية الغرفة، إشارة البدء، مزامنة الحالة، وتمرير مدخلات اللاعب بين عميلين. |
| 9 | تصدير حزمة Android المضمّنة | نجح: تم توليد `index.android.bundle` و46 مورداً بصورة مستقلة قبل تغليف Gradle لتفادي ضغط الذاكرة. |
| 10 | بناء وفحص APK الإصدار | نجح: `:app:assembleRelease` اكتمل بنجاح، وتحقق توقيع APK بمخطط v2. |
