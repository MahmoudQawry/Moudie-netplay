# Moudie NetPlay — سجل تحقق الإصدار 1.4.7

**تاريخ التحقق:** 19 أغسطس 2026

**حزمة التسليم:** `MoudieNetPlay-v1.4.7-startup-fix-arm64-release.apk` لنظام Android `arm64-v8a`

**معرّف التطبيق:** `com.app.moudienetplay`
**رقم البناء:** `30`

## نطاق الإصدار

يعالج الإصدار `1.4.7` بقاء التطبيق على شاشة الشعار. كان مسار JavaScript يحجز شاشة البداية الأصلية قبل تركيب أول واجهة React Native؛ لذلك يمكن أن يبقى المستخدم محجوباً إذا تعذر تحميل الواجهة قبل تنفيذ مؤثر React. أزيل هذا الحجز من JavaScript، وعادت شاشة البداية إلى الإخفاء التلقائي عند ظهور محتوى React Native.

أضيفت أيضاً مهلة احتياطية أصلية مدتها أربع ثوانٍ في `MainActivity`. إذا تعذر وصول واجهة JavaScript إلى أول إطار لأي سبب، يحرر Android شاشة الشعار بدلاً من إبقائها ظاهرة بلا نهاية. تلغى المهلة عند تدمير النشاط، ولا تؤثر في المسار الطبيعي الذي يخفي فيه React Native شاشة البداية أسرع.

## نتائج التحقق

| الدورة | نطاق التحقق | النتيجة |
|---:|---|---|
| 1 | اختبارات تطبيق Android `pnpm test` | نجح: 15 ملف اختبار ناجحاً، 32 اختباراً ناجحاً، وملفان متخطيان متوقعان. |
| 2 | اختبار حماية شاشة البداية الجديد | نجح: يثبت عدم استدعاء `preventAutoHideAsync` ويثبت وجود مهلة Android الأصلية لإخفاء الشعار. |
| 3 | فحص TypeScript `pnpm check` | نجح: لا أخطاء TypeScript. |
| 4 | فحص ESLint `pnpm lint` | نجح: لا أخطاء أو تحذيرات ESLint؛ ظهر تنبيه Node عام عن نوع ملف الإعداد. |
| 5 | تجميع Kotlin `:app:compileReleaseKotlin` | نجح: تم تجميع `MainActivity` بعد إضافة المهلة الأصلية. |
| 6 | حزمة Metro | نجح: تضمين JavaScript و46 مورداً في ملف الإصدار. |
| 7 | بناء Android Release | نجح: اكتمل `:app:assembleRelease` لمعمارية arm64-v8a. |
| 8 | فحص الحزمة والتوقيع | نجح: حزمة JavaScript موجودة داخل APK، والتحقق من APK Signature Scheme v2 ناجح بموقّع واحد. |
