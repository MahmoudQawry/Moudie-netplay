# خدمة الصوت والمشاهدة الجماعية

تحتوي هذه الملفات على بنية تشغيل Moudie للصوت الجماعي والمشاهدة لعدد يصل إلى عشرة أعضاء في الغرفة. تعتمد الخدمة على SFU للصوت وTURN لعبور NAT، بدلاً من شبكة هاتف-إلى-هاتف التي تتدهور عند زيادة عدد الأعضاء.

## ما يقدمه التطبيق الآن

خادم Moudie يصدر رمز وصول قصير العمر لمسار `rooms.mediaToken` بعد التحقق من رمز عضوية الغرفة. يمنح اللاعب والمضيف صلاحية نشر الصوت والاشتراك في المسارات، بينما يمنح المشاهد صلاحية الاستماع والاشتراك فقط. لا تُرسل مفاتيح LiveKit أو TURN إلى APK.

## ما يلزم للنشر الفعلي

1. جهّز خادم Linux دائمًا بعنوان عام وDocker، ثم انسخ هذا المجلد إليه.
2. انسخ `.env.example` إلى `.env` واستبدل جميع القيم بسرّيات طويلة وعنوان IP عام ونطاقين مع TLS.
3. انسخ `turnserver.conf.template` إلى `turnserver.conf` واستبدل `REPLACE_WITH_*` بالقيم الحقيقية.
4. اضبط متغيرات `LIVEKIT_URL` و`LIVEKIT_API_KEY` و`LIVEKIT_API_SECRET` نفسها في خادم Moudie API.
5. افتح منافذ TCP 7880 و7881، وUDP 50000–50100 لـ LiveKit، وTCP/UDP 3478 وTCP 5349 ومجال UDP 49160–49260 لـ TURN.
6. شغّل `docker compose --env-file .env up -d`، ثم اربط تطبيق Android بعميل LiveKit في مرحلة النشر.

> صندوق التطوير المؤقت لا يصلح لتشغيل SFU أو TURN 24/7. لا تشغّل هذه الملفات محليًا في جهاز التطوير كبديل لخادم عام دائم.

## الأمان

لا تحفظ `LIVEKIT_API_SECRET` أو `TURN_SHARED_SECRET` في Git أو داخل APK. استخدم مفاتيح قصيرة العمر، وجدّد الرمز عند إعادة اتصال المستخدم. وتأكد من أن بث اللعبة للمشاهدين لا يمنحهم صلاحية نشر أو إرسال مدخلات للمحاكي.
